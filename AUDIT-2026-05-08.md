# Auditoria do site Boldfy — 2026-05-08

> Stack auditada: Next.js 16.2.2 · React 19.2.4 · Tailwind 3.4 · Radix · @vercel/kv · Notion + ActiveCampaign + Cal.com.
> Escopo: `/src` (excluindo `node_modules`, `.next`, `.git`, `_archive`).

---

## TL;DR — o que fazer primeiro

**Top 5 ações de maior impacto/menor esforço:**

1. Migrar fontes para `next/font/google` (hoje carrega `<link>` síncrono do Google Fonts → ~200ms de TTFB).
2. Adicionar **validação com zod** nas 5 server actions e bloquear enumeração em `/proposta/[id]`.
3. Atualizar `lucide-react` (instalado `1.7.0` da era pré-Lucide; atual é `0.5xx` — quebra de versionamento).
4. Apagar `_archive/`, `use-case-page.tsx` órfão, e 2 imagens não referenciadas em `/public`.
5. Adicionar `poweredByHeader: false` + CSP no `next.config.ts` e remover `console.log` de server actions.

**Resultado esperado:** ~300–500ms de TTFB economizado, hidratação ~150KB menor, hardening real (proposal não enumerável, forms com schema), repo ~10 arquivos mais limpo.

## 2. Performance — quick wins de TTFB e bundle

### P0 (1 dia de trabalho, ~300ms ganhos)

**Fontes via `<link>` ao invés de `next/font`** — `src/app/layout.tsx:132-145`. Hoje:

```tsx
<link href="https://fonts.googleapis.com/css2?family=Inter..." rel="stylesheet" />
```

Render-blocking, sem preload automático, sem fallback metric, sem variable CSS integrado ao Tailwind. Migrar para:

```tsx
import { Inter, Nunito_Sans } from 'next/font/google';
const inter = Inter({ subsets: ['latin'], variable: '--font-sans', display: 'swap' });
const nunito = Nunito_Sans({ subsets: ['latin'], variable: '--font-headline', display: 'swap' });
```

E no Tailwind: `fontFamily: { sans: ['var(--font-sans)', ...], headline: ['var(--font-headline)', ...] }`.

**`html-to-image` carregado eagerly em `proposal-builder.tsx`** (~100KB). Trocar por `await import('html-to-image')` dentro do handler de export.

**`console.log` em server actions** (`proposal-leads.ts`, `contact-leads.ts`, `demo-leads.ts`) — limpar e adicionar regra `no-console` no ESLint, com exceção para `console.error`.

**`next.config.ts` faltando:**

```ts
poweredByHeader: false,
compress: true,
experimental: {
  optimizePackageImports: ['lucide-react', '@radix-ui/react-dialog',
                          '@radix-ui/react-dropdown-menu', '@radix-ui/react-navigation-menu'],
},
```

**Imagens com `<Image>` sem `sizes`** em `use-cases.tsx`, `product-motion.tsx`, footer/header avatares — causa CLS no LCP.

### P1 (uma sprint)

**`'use client'` excessivo nas seções da home** — `hero`, `problem`, `use-cases`, `product-motion`, `solutions-bento`, `manifesto`, `cta-final` estão todas como client-only. Apenas `roi-simulator` (slider + state) e `faq` (accordion) **precisam** ser client. Animações de hero (`hero-float`, `hero-blink`) já são CSS keyframes — não precisam de `useEffect`.

**Plano:** mover hero/problem/use-cases/manifesto para Server Components. Encapsular qualquer sub-componente interativo em ilhas client (`<HeroFloatingCards />`, `<ProblemTimeline />`). Estimativa: ~80KB a menos de hidratação na home.

**Caching das chamadas Notion** — `src/lib/notion.ts` não usa `unstable_cache` nem `cache()`. Cada revalidação ISR (5 min) chama Notion do zero. Wrappar `getPublishedPosts` e fetch de blocks reduz quota e tempo.

**`prefers-reduced-motion`** — animações infinitas em `hero-float-*` e `hero-blink` rodam mesmo offscreen e ignoram preferência de redução de movimento. Adicionar `@media (prefers-reduced-motion: reduce)` em `globals.css` zerando essas animações.

### Versão de dependência crítica

**`lucide-react@1.7.0` é da era Feather/pré-Lucide (2022).** Atual estável é `0.5xx.x`. Atualizar requer mudar import path e provavelmente alguns nomes de ícones — vale a pena ler changelog. Bundle atual provavelmente carrega ~3× mais código que o necessário.

## 3. Segurança — gaps reais

### P0

**a. Server actions sem validação de input** (`/src/app/actions/*.ts` — todas as 5).
Hoje confiam no tipo TypeScript em runtime. Adicionar zod:

```ts
const BetaLeadSchema = z.object({
  nome: z.string().min(1).max(100),
  email: z.string().email(),
  telefone: z.string().regex(/^\+?\d{10,15}$/),
  empresa: z.string().min(1).max(120),
  // ...
});
export async function createBetaLead(input: unknown) {
  const data = BetaLeadSchema.parse(input);
  // ...
}
```

**b. Enumeração de propostas em `/proposta/[id]/route.ts`.** O ID é o page-id Notion (32 chars hex), publicamente acessível, sem auth. Como Notion gera IDs sequenciais por database, é tecnicamente possível enumerar e coletar pricing de outras propostas. Mitigação:

- Gerar token assinado (HMAC) ao criar a proposta e validar via query param: `/proposta/[id]?t=...`.
- Adicionar `noindex` em `robots.ts` para `/proposta/*` (já está bloqueado, confirmar).
- Rate-limit por IP via `@vercel/kv` (já instalado mas não usado).

**c. Webhook do Cal.com tem fallback inseguro.** `src/app/api/webhooks/cal/route.ts:98-108` aceita requisições não-assinadas se `CAL_WEBHOOK_SECRET` estiver ausente. Em produção isso permite forjar eventos. Trocar por `throw` se a env não existir em prod.

### P1

**Sem rate limiting em forms.** `@vercel/kv` está instalado mas não é usado em lugar nenhum. Adicionar throttle por email+IP nas 5 server actions (limite tipo: 5 submissions/hora por email).

**Sem Content-Security-Policy.** `next.config.ts:3-16` tem HSTS, X-Frame, Referrer, Permissions — mas falta CSP. Baseline pra fechar XSS via script externo:

```ts
{ key: 'Content-Security-Policy', value: [
  "default-src 'self'",
  "script-src 'self' 'unsafe-inline' www.googletagmanager.com www.google-analytics.com snap.licdn.com *.activehosted.com",
  "style-src 'self' 'unsafe-inline' fonts.googleapis.com",
  "img-src 'self' data: https:",
  "font-src 'self' fonts.gstatic.com",
  "connect-src 'self' *.notion.com *.activehosted.com www.google-analytics.com px.ads.linkedin.com",
  "frame-ancestors 'none'",
].join('; ') }
```

**`.env.example` desatualizado.** Faltam: `NOTION_PROPOSTAS_DB_ID`, `NOTION_CRM_EMPRESAS_DB_ID`, `NOTION_CRM_PESSOAS_DB_ID`, `NOTION_CRM_INTERACOES_DB_ID`, `CAL_WEBHOOK_SECRET`, `NEXT_PUBLIC_SITE_URL`.

**`/api/contact/route.ts` é state-mutating sem nenhum check de origem ou auth.** Como ainda só faz `console.log`, não é exploit hoje — mas quando integrar com email/CRM (TODO existente), precisa origin check ou trocar por server action.

### P2

- `proposal-leads.ts:244` loga `errText` da Notion — pode vazar estrutura interna em logs do Vercel.
- Validação fraca do formato do `id` em `/proposta/[id]` antes de chamar Notion.

### P1

- `openGraph` ausente em `/para/marketing`, `/para/vendas`, `/para/rh`, `/ferramentas`, `/legal`. Cada uma deveria ter sua própria imagem OG (1200×630) ou pelo menos definir explicitamente para herdar com `images: undefined`.

- Sem `Skip to main content` link — não é blocker, mas melhora navegação por teclado.

### P2

- FAQ Section já tem `FAQPage` schema — ✓.
- Sitemap inclui blog dinamicamente — ✓.
- Estrutura de heading parece OK no spot check, mas precisa varrer `*-client.tsx` (LPs longas) pra confirmar 1 `<h1>` por página.

## 5. ESLint / DX — endurecer guardrails

`eslint.config.mjs` hoje só usa presets do Next sem regras custom. Adicionar:

```js
rules: {
  'no-console': ['warn', { allow: ['warn', 'error'] }],
  '@typescript-eslint/no-explicit-any': 'warn',
  '@typescript-eslint/no-unused-vars': ['warn', { argsIgnorePattern: '^_' }],
  'react/jsx-no-target-blank': 'error',
}
```

Adicionar script no `package.json`:

```json
"scripts": {
  "lint": "eslint",
  "typecheck": "tsc --noEmit",
  "lint:fix": "eslint --fix"
}
```

Sem `typecheck` rodando hoje, regressões de tipo passam batido.
